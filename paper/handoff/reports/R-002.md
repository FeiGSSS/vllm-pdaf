## Answer

- **E2e (C12):** in 6P2D, with the bytes Dynamo actually transfers, the
  handoff is about 3–4.5% of TTFT for 16–32K contexts (≤7% even with
  full-prompt bytes). Larger-Decode splits are below 3%. Fan-in into one
  Decode GPU divides its ~8.6 GB/s ingress, so each of three concurrent
  transfers takes 3.0–3.3× longer; September's C30 runs show no such slowdown
  (151–163 ms per transfer).
- **E2a (C13):** no single knob beats either baseline with a CI excluding
  zero; both baselines are kept unchanged.
- **E2b (C14):** "contrary result removed". Best PAP / PD 6P2D capacity is
  1.24 (Strict), 1.36 (Standard), 1.27 (Relaxed); July was 0.68 / 0.63 /
  0.76. Both fairness checks pass.

## Deviations from the request

- **E2b dataset:** session-isolated L07 (X-002); not byte-compared with July
  (original file not on the host), but same parameters and identical sampled
  append mean.
- **E2b grid:** both PAP topologies were still feasible at their top point,
  so PAP was extended to C56/C64/C72 and then C96 (one coarse step instead of
  +8 steps). 7PA1P stays Standard-feasible at C96 but its goodput falls from
  the C72 peak (17.20 vs 18.45), so capacity is at C72; 6PA2P becomes
  Standard-infeasible at C96 (TTFT P95 10.4 s).
- **E2e "same switch":** no GPU pair shares a PCIe switch on this host; the
  1→1 case uses a same-NUMA pair (6→7, NODE).
- **E2e(a) per-request transfer:** Dynamo logs NIXL statistics per time
  window only, so per-request shares are bounds (`d2ft`, `xfer_est`), not
  direct measurements.

## Validity and limitations

- E2a: 21/21 valid after 3 reruns. Three DP8 runs failed at start because the
  previous service still held GPU 0 (no wait in `run_all.sh`); they are kept
  and excluded. E2b's `run.sh` waits for idle GPUs; 71/71 E2b runs valid.
- E2e microbenchmark: 5 timed repetitions per point, no PCIe/AER/GHES event in
  the kernel log.
- An exp-agent scheduling error left the GPUs idle for about 2 hours between
  E2b rounds; no run was affected.
- E2b ran with closed-loop concurrency and July's think/tool delays; PAP
  capacity is limited by TTFT, PD's by ITL.

## Unexpected findings / suggested follow-ups

- DP8's collapse on L07 (see Decisions 2).
- 7PA1P > 6PA2P on L07 and on the September C30 runs: a second Projection GPU
  is not worth a Prefill GPU at these output lengths; relevant to R-004 A2.
- Fan-in: R-003's PD runs at C40–C60 will carry `ttft_breakdown.json`; I will
  report per-run transfer time against load there, which tests whether the
