# Read-only L20B/L20T runtime comparison

Actual loaded kernel7.0.0-31, NVIDIA open driver595.84, GPU VBIOS95.02.7C.00.06 on all8 GPUs, ConnectX-7 firmware28.43.2026, in-kernel mlx5 modules, BIOS01.07.00 dated2025-10-16, boardNF5468-A8-A0-R0-00 and AMD microcode0xb002161 match across hosts. Both boot with amd_iommu=off and neither has nvidia_peermem loaded. NVIDIA module params differ only in RmProfilingAdminOnly (B=0,T=1), a profiling-permission setting; no causal evidence links it to AER0x14000.

Actual libucp/libuct/libuct_ib, external NIXL UCX plugin, and NIXL core SHA256 match between hosts. Binding import selects nixl_cu13 version1.3.2. Plugin build metadata labels source project1.2.0; this alone does not establish ABI incompatibility. A metadata-only NIXL agent with backends=[], progress/listen threads disabled accepted UCX plugin; no UCX backend instance or memory registration created. Process maps showed one set of intended local UCX1.22 RDMA libraries and wheel core/common libraries. Installed nixl_cu13 API and14 installed vLLM NIXL Python files match installation RECORD hashes. Upstream plugin API is versioned separately: <https://github.com/ai-dynamo/nixl/blob/main/docs/BackendGuide.md> . No repair made for an unproven version mismatch.

Roles are NOT equivalent: vLLM installed pull_worker.py329–340 submits NIXL READ on Decode. L20B receives KV and computes Decode; L20T provides Prefill KV. No hardware-error pstore attachments found in readable T journal; that is only a log-source negative and does not establish same-role stability.

Memory path: installed vLLM base_worker chooses VRAM and use_host_buffer=false for cuda. Current UCX capabilities: cuda_cpy can export cuda dmabuf; IB domain can register dmabuf. IB domain listing host/rdma without cuda is NOT evidence that GDR is unavailable: UCX separately advertises DMA-BUF registration. Official matching UCX v1.22.0 source ucp_mm.c623–674 queries a provider fd and passes it to consumer MD; ib_md.c519–523 calls ibv_reg_dmabuf_mr. nvidia_peermem absence therefore does not disprove direct GPU registration. Current configuration GPU_DIRECT_RDMA=try, CUDA_COPY_DMABUF=try, PCI_RELAXED_ORDERING=auto. Actual historical MR/file-descriptor/protocol choices were not recorded, so do not call a specific transfer path directly measured merely from these capabilities. Sources saved in read-only-sources/ucx-v1.22.0; source URLs <https://raw.githubusercontent.com/openucx/ucx/v1.22.0/src/ucp/core/ucp_mm.c> and <https://raw.githubusercontent.com/openucx/ucx/v1.22.0/src/uct/ib/base/ib_md.c> .

Conclusion: this audit found no simple cross-host driver/firmware/binary mismatch, and did not establish a plugin ABI defect. Shared software defects remain possible because roles differ. Direct machine-stop mechanism remains six GPU PCIe Completion Timeout+Unexpected Completion -> GHES fatal panic. It is not justified to equate RDMA READ direction with the PCIe request whose completion timed out: exact original requester/tag/address missing from zero TLP header.

No inference services, cross-host data transfers, GPU allocations, stress tests, BIOS writes or driver changes in this audit. Metadata-only plugin loading instantiated no backend. No additional postmortem upload attempted. Root cause remains unresolved; this report narrows hypotheses without claiming a fix.
