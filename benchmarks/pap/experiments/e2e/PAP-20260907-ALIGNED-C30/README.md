# DP / PD / PAP comparison at concurrency 30

同一组五种架构各两次，共 10 次运行、1800 个请求；客户端并发从 60 改为 30，
会话数仍为 60，每会话三轮。模型、native-32K 数据集、调度预算和路由参数沿用上一组。

| 架构 | TTFT (s) | ITL (ms) | TTFT 较 C60 | ITL 较 C60 |
| --- | ---: | ---: | ---: | ---: |
| dp8 | 2.208 | 77.383 | -42.24% | -46.40% |
| 6p2d | 5.698 | 48.991 | -62.22% | +6.73% |
| 4p4d | 10.980 | 28.375 | -63.56% | +7.61% |
| 2p6d | 34.734 | 25.114 | -46.92% | +0.01% |
| pap7pa1p | 5.364 | 44.850 | -63.10% | +3.05% |

表中为两轮客户端逐请求指标的平均值，负百分比表示下降。ITL 直接使用
AIPerf `inter_token_latency`：每个请求生成阶段的平均 token 间隔。因此 ITL
分位数是请求级平均 ITL 的分布，不是将所有 token gap 混合后的分布，也不是
GPU step 耗时。各轮值、p50、历史选择器 p95 和范围见
[comparison.json](results/comparison.json)。

两轮共 360 个请求合并后，按 AIPerf 使用的线性百分位方法重新计算尾延迟：

| 架构 | TTFT P95 (s) | TTFT P99 (s) | ITL P95 (ms) | ITL P99 (ms) | E2E P95 (s) | E2E P99 (s) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| dp8 | 5.661 | 7.909 | 132.822 | 162.697 | 15.956 | 21.393 |
| 6p2d | 9.822 | 10.703 | 66.042 | 69.246 | 15.370 | 18.754 |
| 4p4d | 14.446 | 15.930 | 33.553 | 35.623 | 17.888 | 19.666 |
| 2p6d | 60.652 | 65.560 | 27.223 | 27.488 | 63.509 | 67.581 |
| pap7pa1p | 9.557 | 12.245 | 53.583 | 57.026 | 14.344 | 16.493 |

两轮客户端实际 phases 配置均为 sessions=60、concurrency=30；每轮 180 个请求。
输入文件哈希和各会话轮次输出长度相同；后续 prompt 含实际生成反馈。所有正式
运行均通过有效配置、启动拓扑、真实进程和 GPU 映射、正确性及清理审计。

DP/PD 使用官方 Dynamo 1.4.1 / vLLM 0.26.0，PAP 使用提交 `bdb0954c75`。
与 C60 测量相比，该提交将回收边界的 CUDA 同步 API 换成 accelerator 同步 API，
此前已验证 CUDA 行为。因此这里是同负载的配置对比，不能声称严格单变量因果实验。
各架构的专有 Graph / 显存策略仍不同，两次重复不足以建立稳定优劣结论。

没有配置 goodput SLO；原始逐请求延迟与时间戳保留，可后续统一阈值计算。

## GPU telemetry

AIPerf 为每次运行保存了八张物理 GPU 的 DCGM 时间序列。下表只使用客户端请求
窗口，两轮合并后按所有 GPU 时间样本求平均：

| 架构 | GPU 利用率 (%) | 显存活动率 (%) | 单卡功率 (W) | 单卡温度 (°C) |
| --- | ---: | ---: | ---: | ---: |
| dp8 | 89.534 | 40.161 | 298.571 | 61.402 |
| 6p2d | 90.102 | 33.244 | 302.531 | 63.992 |
| 4p4d | 89.485 | 48.371 | 283.078 | 61.657 |
| 2p6d | 43.270 | 21.981 | 184.858 | 51.156 |
| pap7pa1p | 90.052 | 31.828 | 288.791 | 60.851 |

这些是物理 GPU 粒度的采样结果。PAP 的 Prefill 和 Attention 共用 GPU，无法用
这份 telemetry 将二者单独归因。完整字段还包括显存占用、DRAM、计算引擎、
Tensor Core 活动、能耗和 XID 计数，均保存在逐运行原始归档中。

## 原始记录与复核

`results/archives/` 无损保留十次运行的全部普通文件及原始执行协议，
`results/configs/` 展示 requested/effective 配置和主要审计。逐文件 SHA256
见 `results/manifest.json`；结果总清单为 `results/SHA256SUMS`。

从仓库根目录离线校验并复算：

```bash
.venv/bin/python benchmarks/pap/experiments/e2e/PAP-20260907-ALIGNED-C30/verify.py
```

附加 `--extract-to /tmp/pap-c30-restored` 可解压到一个尚不存在的目录。
原始协议和配置中的绝对路径用于追溯当时运行；不覆盖历史结果。新测量使用共享
runner，创建独立 `runs/<timestamp>/` 并沿用完整拓扑和配置审计。
