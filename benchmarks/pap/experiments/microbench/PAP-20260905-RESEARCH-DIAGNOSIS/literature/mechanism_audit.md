# Closest prior mechanisms and remaining uncertainty

Audit date: 2026-09-05. This is a bounded literature collision audit, not a novelty certificate. The complete broad six-API retrieval (19 unique records, including noise and errors) is in [allinone.md](allinone.md). Primary methods were read in the archived full-text JSON bundles below. No repository source, topology, or experimental result was sent to an external retrieval service.

## Units and expected dependency model

A **request** is one user generation. A **decode step** generates one next token for that request. A **layer task** executes one operator group for a `(request, step, layer)` tuple. A **batch** is a set of compatible tasks submitted together; a **microbatch** is a partition of a larger scheduled batch. A **queued batch** has not been dispatched; an **in-flight batch** has outstanding execution or communication. A GPU **CTA task** is smaller than a serving batch. These units are not interchangeable.

Expected exact-transformer transition: layer input → Q/K/V projection and KV append → attention over all required context (possibly decomposed into exact partial outputs) → complete attention-result merge → output projection/FFN → next layer. Independent requests can occupy different transitions simultaneously. FFN cannot consume an arbitrarily incomplete attention result: its dependency is per-request completion of the required attention output, not merely arrival of some KV fragments. Batching FFN work generally requires the same model/layer weights and compatible execution format. Cross-batch regrouping is a scheduling policy over this DAG, not permission to remove mathematical dependencies.

## Ten closest verified works

All residue descriptions below are **not observed in the inspected sections**, not claims that the papers or their current code categorically cannot implement them. Performance numbers are deliberately omitted: published benchmarks use different workloads and hardware.

| **CrossPool: Efficient Multi-LLM Serving for Cold MoE Models through KV-Cache and Weight Disaggregation** (2026 preprint), [§3–4](https://arxiv.org/html/2606.24506v1#S3) | Separate FFN-weight and KV pools; attention and non-FFN work stay KV-local; only hidden states cross pools. Two in-flight batches carry independent model IDs, layer cursors, and completion state. Finishing one batch does not stop the other: §3.2 explicitly avoids a global layer barrier across models. Persistent GPU kernels poll per-model queues, select ready batches, dispatch captured subgraphs, communicate, and update state. | Implemented focus is cold-MoE decode, captured batch sizes 1–4, a two-batch state machine. It does not establish a physical-shared-prefix cohort objective, fragment-level regrouping across many serving batches, or KV byte-time/release-aware admission. These must be compared against its actual mechanism, not against an invented globally synchronous baseline. |
| **Efficient Heterogeneous Large Language Model Decoding with Model-Attention Disaggregation** / **Lamina** (2024, revised 2025), [§3–5](https://arxiv.org/html/2405.01814v2#S3) | Memory-specialized devices retain KV and compute attention; compute devices run the rest. Sends Q early, computes previous-token attention while K/V projection/transfer proceeds, then exactly combines old/new partial outputs. Rotational staggered pipelining shares an attention-device pool across multiple batches/model replicas and migrates execution contexts, not retained KV. | Its inspected implementation chooses head-level sharding and a balanced rotational pipeline; request sharding is discussed as potentially imbalanced. Dynamic physical-prefix grouping and release-sensitive request-level scheduling were not demonstrated. “Pooled attention,” “move compute, not KV,” and exact early-Q overlap are already covered. |
| **MegaScale-Infer: Serving Mixture-of-Experts at Scale with Disaggregated Expert Parallelism** (2025 preprint title), [§4–5](https://arxiv.org/html/2504.02263v4#S4) | Attention/FFN separation, independent parallelism and hardware assignment, microbatch ping-pong across layers, communication overlap, and M2N transport removing host-copy/control costs. The paper explicitly models individual-microbatch iteration latency separately from global-batch completion. | A different scheduling unit or straggler policy may distinguish a design, but simple cross-layer overlap or elastic A/F provisioning does not. The inspected section divides a scheduled batch into microbatches; it does not establish prefix-memory-aware online cohort selection. |
| **Making MoE-based LLM Inference Resilient with Tarragon** (2026 preprint), [§3, §5.2](https://arxiv.org/html/2601.01310v2#S5.SS2) | Reconfigurable AW↔EW datapath and independent worker recovery. For **each expert and layer**, an EW buffers incoming tokens and starts when all healthy AWs have contributed **or** a minimum efficient batch size is reached. It explicitly removes the implicit all-AW barrier and proceeds with partial inputs from the distributed worker set. | This directly collides with “same-layer FFN on a ready subset.” Its objective is failure masking; shared-prefix reuse, deadline-sensitive cohort formation, and cache release/byte-time trade-offs were not observed. A new policy must improve more than the threshold rule under failure-free heterogeneous attention completion. |

| **POD-Attention: Unlocking Full Prefill-Decode Overlap for Faster LLM Inference** (2024 / ASPLOS 2025), [§4](https://arxiv.org/html/2410.18038#S4) | One hybrid prefill/decode attention kernel with SM-aware CTA binding. CTAs read SMID/counters, choose prefill or decode, and switch if that operation’s CTA work is exhausted. Independent CTA completion and CTA-local barriers avoid cross-operation synchronization interference. | This is intra-kernel resource sharing over a preconstructed hybrid work set, not an asynchronous multi-layer serving queue. Nevertheless, runtime SM pooling and compute/memory complementarity are established. A scheduler above it must show an incremental effect after enabling POD-like efficient hybrid kernels. |
| **Hydragen: High-Throughput LLM Inference with Shared Prefixes** (2024 / ICML 2024), [§3](https://arxiv.org/html/2402.05099v2#S3) | Exact prefix/suffix decomposition, log-sum-exp output recombination, inter-sequence query batching over one shared KV prefix, and hierarchical tree-shaped sharing. Converts repeated prefix matrix-vector work into reuse-friendly matrix-matrix work. | “Reuse shared prefix across requests” and hierarchical common-prefix grouping are covered. Its inspected presentation operates on an attention invocation’s batch; asynchronous **cross-serving-batch arrival/cohort selection** is a distinct policy question, not a new attention identity. Mere enlargement or relabeling of the batch is insufficient novelty. |
| **FlashInfer: Efficient and Customizable Attention Engine for LLM Inference Serving** (2025), [§3.1.2, §3.3](https://arxiv.org/html/2501.01005#S3.SS1.SSS2) | Composable sparse formats group shared-prefix rows into dense reusable submatrices using index arrays **without moving KV data**. Length-aware planning maps ragged work to persistent CTAs and exact partial-result contraction, compatible with CUDA Graphs. CPU plan is reused across layers. | “Ragged attention,” “shared-prefix grouping without KV copy,” and “persistent attention workers” are covered. The paper’s runtime plan is CPU-computed per generation step, not the same as an online multi-pool request-deadline scheduler. Its index-based shared-prefix kernel should be an enabled baseline for any claimed new cohort policy. |
| **NanoFlow: Towards Optimal Large Language Model Serving Throughput** (2024 preprint), [§4](https://arxiv.org/html/2408.12757#S4) | Operation-granularity nano-batches, intra-device overlap of compute/memory/network work, execution-unit allocation, interference-aware pipeline search, and asynchronous CPU request/KV management. | Co-location plus microbatch/resource overlap is established. Its throughput-oriented intra-device pipeline is not itself evidence of physical-prefix cache-lifetime optimization or barrier-free cross-pool request progress. These distinctions must be measured against a well-tuned pipeline, not against serial operation launch. |
| **Huawei Cloud Model-as-a-Service on the CloudMatrix384 SuperPod** (2025, v6 inspected), [§5.2–5.3](https://arxiv.org/html/2508.02520v6#S5.SS2) | Implemented large-scale attention/MoE separation, DP domains plus microbatches, asymmetric A2E/E2A communication, and three persistent NPU receive/compute/send loops. | Important negative boundary: §5.3 labels fully asynchronous barrier-free distributed dataflow a **vision**; current A2E/E2A remain synchronized and susceptible to stragglers. Do not misreport that vision as a completed system, but do not claim persistent control or domain overlap as new. |

## Other requested names, collisions, and exclusions

- **FlowKV is ambiguous.** The relevant systems paper is [FlowKV: A Disaggregated Inference Framework with Low-Latency KV Cache Transfer and Load-Aware Scheduling](https://arxiv.org/html/2504.03775) (2025): reorganized KV transfer and dynamic P/D role/load balancing. It **transfers** KV and is not KV-local operator disaggregation. A different [FlowKV paper](https://arxiv.org/abs/2505.15347) compresses only the latest completed conversational turn to preserve older compressed context; it is not the same system.
- **FlowServe is real, but not a verified standalone paper title.** It is the serving engine in [DeepServe: Serverless Large Language Model Serving at Scale](https://arxiv.org/html/2501.14417), whose original search-index title is **DeepFlow**. §4.2 describes host-centralized async scheduling, prefix-cache readiness, and pipeline microbatch management. §4.5 describes operator disaggregation as active work; the later CloudMatrix paper is stronger implemented evidence. Do not cite the unrelated commercial FlowServe product as this system.
- **Para, PAF, AttentionServer, and standalone POD-disaggregation:** exact-name searches did not establish primary serving papers with these names in the intended sense. PAF searches predominantly returned a parallel attention/FFN **model-architecture** motif and unrelated acronyms. This is unresolved identity, not proof of nonexistence. POD-Attention is verified and must not be silently renamed into a disaggregation system. Search traces retain even irrelevant name hits.
- [How Far Can Disaggregation Go? A Design-Space Exploration of Attention–FFN Disaggregation for Efficient MoE LLM Serving](https://arxiv.org/html/2605.28302v1) (2026) models batch-overlapped AFD across compute/communication stages and includes a vLLM implementation appendix. It is another counterexample to treating AFD batch overlap as new. Its simulation/placement scope must not be confused with a measured arbitrary online scheduling policy.
- [Cascade Inference](https://flashinfer.ai/2024/02/02/cascade-inference.html) (2024, primary project article) independently describes exact shared-prefix batch attention and merge. It is archived with the primary papers and reinforces the Hydragen/FlashInfer collision; it is not an invented additional conference paper.

## Claim-by-claim disposition

1. **Avoid a global attention/projection or A/F barrier:** already directly covered at heterogeneous batch/layer scope by CrossPool, same-layer expert ready-subset scope by Tarragon, and dependency-task scope by MPK. A blanket novelty claim is untenable. These mechanisms have different units; establish the exact proposed unit first.
2. **Reuse a shared prefix across batches:** shared physical KV reuse and inter-sequence batching are covered by Hydragen, Cascade, and FlashInfer. Cross-time grouping of independently arriving layer-ready tasks may leave a policy question, but “across batches” can simply be a renamed larger batch. Establish which requests are already submitted/running when a new query becomes ready and whether a useful KV tile remains resident at that boundary.
3. **Pool memory without KV migration:** Lamina and CrossPool are direct architecture counterexamples; FlashInfer adds index-only shared-prefix formatting. Distinguish no *decode pool-boundary migration* from no KV movement anywhere: Lamina still transfers prefill KV to attention devices.
4. **GPU-resident scheduler:** POD-Attention, CrossPool, MPK, and CloudMatrix cover several levels. State whether the new control concerns CTA assignment, operator DAG dispatch, per-layer batch dispatch, or serving admission.

## Narrow residual and required follow-up—not a novelty claim

A possible remaining research question combines physical-prefix cohort formation with same-layer FFN efficiency and a **KV lifetime/byte-time** objective under SLOs. None of the ten inspected mechanisms establishes that precise joint objective. This does **not** prove it is novel; it is a more discriminating next collision search.

This bounded audit did not perform a complete search for shared-KV **last-reader release**, byte-time/memory-time scheduling, eviction-aware serving, or SLO-aware common-prefix cohort policies. Cached KV is not automatically releasable after a kernel’s last reader: reusable cache ownership and temporary execution pins have different lifetimes. Any claimed release policy must specify whether it frees a pin, request-owned suffix blocks, or a reusable shared-prefix object. It must account for consumers already enqueued or in flight and for transport completion, not only kernel submission.

Before declaring a contribution, search that exact residue and compare against: (a) CrossPool independent batch cursors; (b) Tarragon all-healthy-or-minimum-efficient-subset dispatch; (c) FlashInfer/Hydragen with prefix grouping enabled; (d) an MPK-like dependency scheduler. A one-variable ablation must keep workload, topology, device mapping, kernels, cache-hit structure, FFN batch policy, and clients equal. Report request/step residence, per-token latency, cadence, goodput, transferred bytes, and occupied KV byte-time separately. Throughput or latency ratios alone cannot establish the proposed mechanism.
